## v2.1.9 - 2026-10-10

- Автопроверка доступности шлюза (opt-in): после трёх подряд неудачных свежих проверок текущего маршрута по умолчанию (любой тип сервера; повтор каждые 60 с, то есть около 3 минут сбоя; любой успех сбрасывает счётчик) монитор переключает шлюз на самый быстрый работающий сервер через общую gateway/HAPP-транзакцию с откатом. Трёхкратное подтверждение введено, потому что на `.39` рабочий Trojan-шлюз дважды подряд не прошёл пробу за 30 секунд, а переключение перезапускает sing-box и HAPP. Устаревший результат пробы, режим вне VLESS, смена списка серверов/настроек посреди цикла не вызывают переключения; события `gateway_check_failed`/`gateway_down`/`failover_no_candidate` пишутся в журнал без дублей.
- Сообщение Mattermost стало шаблоном в Настройках (`{date}`, `{time}`, `{old}`, `{new}`, `{source}`, `{latency}`) с смещением от UTC (по умолчанию `+03:00`); безопасная подстановка по белому списку, пустое поле возвращает текст по умолчанию 📢 «Обновление статуса».
- Полностью удалён внешний WireGuard-клиент: backend/config/status/control endpoints, блок Настроек, polling, status-helper и внешний режим gateway.
- Gateway helper поддерживает VLESS/default без внешнего peer routing/NAT и без WG outbound для HAPP. WireGuard-сервер `wg-easy`, его клиенты и LAN policy сохранены.
- Установщик больше не сохраняет/восстанавливает managed внешний клиент; подтверждённая legacy-очистка сохраняет данные managed WG-сервера.
- Настройки → «Обзор сервера»: карточка «SSD-диск» (всего / занято, ГБ, корневая файловая система), все пять карточек в одной строке на desktop. Время работы берётся из `/proc/uptime` контейнера: на `.39` в установленном unit панели отсутствовал `BindReadOnlyPaths=/proc/uptime`, из-за чего отображался uptime физического хоста; строка добавлена на сервере (в репозитории unit уже содержал её).
- Сброс статистики HAPP очищает накопительный итог, записи «Истории HAPP» и данные скоростей (`download_rate_samples`/`download_rate_counters`) выбранного пользователя. Baseline активных соединений (`traffic_reset_baselines`, очищается по сроку хранения) не даёт вернуться байтам, накопленным до сброса; учитываются только новые. Ранее сброшенные профили не очищаются ретроспективно — для них нужно нажать «Сбросить» ещё раз.
- Блок «Доступ к панели» (смена пароля) перенесён под VIP-ссылку HAPP в Настройках.
- VERSION и CSS/JS revision: `2.1.9` (`2.1.9-failover`). Пройдены 210 Python-тестов, panel JS и HAPP stats UI проверки. Опубликованы тег `v2.1.9` и [GitHub Release](https://github.com/DgekStr/FocusVPN/releases/tag/v2.1.9).
- Документация: README содержит текущую версию, ссылки на релизы, скриншоты и блок-схемы работы сервиса; описания ранних версий перенесены в этот файл и GitHub Releases. Скриншот мобильного HAPP удалён.

## Заголовок панели и счётчики HAPP - 2026-10-09

- В «Настройки → Заголовок и объявление HAPP» поле «Заголовок сервера» задаёт также HTML `<title>` административной панели. После сохранения новое имя появляется во вкладке браузера при следующем открытии или обновлении страницы, без перезапуска службы. Специальные HTML-символы экранируются; при отсутствующих или некорректных настройках используется стандартное имя FocusVPN.
- Объявление подписки содержит отдельные реальные счётчики `DL` и `UL`, например `DL: 512.0 MB / UL: 1.0 GB`. Единицы B/KB/MB/GB/TB выбираются автоматически по основанию 1024; нулевой объём отображается как `0 B`. Счётчики обновляются при запросе подписки, в том числе после ручного обновления в HAPP.
- Заголовок подписки по-прежнему включает имя пользователя с прежним ограничением длины. Авторизация, UUID, ключи, токены подписок и маршрутизация не меняются. Для установки обновления достаточно заменить код панели и перезапустить только `sing-box-admin`; VPN-службы перезапускать не нужно. Версия остаётся `2.1.8`, опубликованные теги и релизы не изменяются.

## Ранние дополнения, включённые в v2.1.8

- Маршрут по умолчанию в таблице VPN-серверов отмечается зелёным индикатором с доступной подписью вместо `active`. Статус службы не меняется.
- Блок «Подключения HAPP» расположен выше «Пользователи HAPP». Высота фиксирована на 880/1120 px, прокрутка и доступ ко всем строкам сохранены. Удалено пояснение под таблицей активного трафика.
- Создание HAPP-пользователя перенесено в модальное окно в стиле панели. Сохранены обязательное имя, необязательный срок UTC и CSRF-защита; работают фокус, сброс формы, отмена, Escape и закрытие по фону. CSS и JS имеют обновлённые адреса для сброса браузерного кэша.
- VIP и персональные HTTP-подписки получают профиль `FocusVPN Direct`: 201 явно заданное `domain:`-исключение идёт через обычное подключение клиента, остальные назначения остаются на VPN. JSON профиля кодируется в Base64 и передаётся строкой `happ://routing/onadd/...` в теле подписки, без большого HTTP-заголовка.
- Имя профиля неизменно, а `LastUpdated=1791417601` обозначает стабильную ревизию правил. UUID, ключи, токены и адреса подписок не меняются; ранее импортированные отдельные VLESS-ссылки продолжают работать, но не получают исключения автоматически.
- После обновления подписки нужно дождаться готовности geo-файлов и переподключить HAPP. Исходный JSON сервера может не измениться: профиль маршрутизации хранится отдельно, а уже запущенный Xray не пересобирается при обновлении подписки. IP-проверки из списка исключений показывают реальный IP клиента.
- Установщик проверяет наличие обязательных модулей, статических файлов и файла версии до системных изменений, копирует весь обновлённый runtime и компилирует Python-код до запуска панели. Рабочие шаблоны, пароль и данные HAPP не заменяются значениями из Git.

При раннем обновлении на сервере проверены семь действующих подписок по LAN и публичному HTTPS, сохранение ключей/UUID/токенов и PID VPN-служб. В Windows HAPP 4.3.0.610 подтверждены импорт, выбор профиля и наличие 200 правил ранней ревизии; прямой выход после клиентского переподключения пока не подтверждён. Полный привилегированный запуск обновлённого установщика требует отдельной тестовой VM.
