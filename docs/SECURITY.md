# Security notes

- Production credentials are excluded from this repository.
- Do not commit VLESS links, UUIDs, Reality keys, Basic Auth hashes, API passwords, QR payloads or SQLite databases.
- Keep `/etc/sing-box-admin/auth.json`, `wg-easy-api.json`, `happ-server.json` and `vless-uri` root-readable only.
- External WireGuard client support is removed in 2.1.9. Private backups of retired client profiles still contain keys: keep them root-only and outside the repository; remove the former runtime profiles/status after migration.
- Mattermost incoming-webhook URLs are secrets. Keep `/etc/sing-box-admin/vless-monitor-settings.json` mode `0600`; never include the URL in API responses, journal events, screenshots, repository files or error output.
- Probe results, automation state and `/etc/sing-box-admin/gateway-switches.jsonl` are private runtime data, not publication artifacts. Checks use temporary loopback SOCKS listeners; candidate files containing credentials are mode `0600` and removed after the test process stops.
- Import and automation settings use the panel session/CSRF boundary. A background check must not change the active route; an automatic switch must recheck mode, configuration and revision before applying.
- TLS verification remains enabled by default. For imported self-signed servers, prefer the explicit SPKI SHA-256 pin; the separate insecure checkbox disables certificate verification and accepts any certificate. A certificate/auth failure must remain visible when neither trust option is selected.
- The standalone installer defaults to public IPv4 HTTPS access on port 7445 through `FOCUSVPN_ADMIN_NETWORK=0.0.0.0/0`, without removing Basic Auth/session authentication or subscription-token checks. The HTTP backend is bound to `127.0.0.1:9443`; wg-easy TCP 51821 remains blocked outside loopback. Restrict the admin CIDR for source-IP filtering; a nonempty explicitly configured CIDR is preserved on upgrade. The application without installer-provided settings still defaults to private networks. Historical LAN/proxy deployments must separately restrict their plaintext backend; network reachability must not be mistaken for confidentiality.
- When using a reverse proxy, set `FOCUSVPN_TRUSTED_PROXY_NETWORKS` to exact proxy IP/CIDRs. Only requests directly received from these peers may supply `X-Real-IP`/`X-Forwarded-Proto`; other clients cannot spoof source-IP access checks or session binding. Proxy TLS sessions receive `Secure` cookies. Since the application allowlist remains `0.0.0.0/0` by request, LAN hosts that can reach `192.168.0.39:9443` can bypass TLS; restrict the host firewall to proxy `192.168.0.15` if TLS must also be mandatory on LAN.
- HAPP QR and deeplink endpoints must remain behind the same authorization boundary.
- The narrowly scoped `/happ-subscription/<token>` route uses a per-account bearer token and the configured source-network filter, not an admin session. It must never expose another account, registry or admin API. Subscription URLs and `happ-subscription-key.json` (mode `0600`) are credentials: do not log, publish or screenshot them. Disabled, expired and deleted accounts must not receive configurations. Plain HTTP exposes these credentials in transit; use HTTPS for untrusted or internet access.
- Persistent HAPP statistics contain sensitive names, source addresses and visited destinations. Keep `/mnt/stat` mode `0700` and `happ-stat.sqlite3`/SQLite sidecars mode `0600`; history, XLS/XML export and full-reset endpoints require panel authentication (the reset additionally requires CSRF and an explicit `confirm=reset-all` field). Do not publish the database, screenshots of real user history, backups or downloaded XLS/XML exports. Retention in the database does not erase external copies or filesystem snapshots.
- VIP snapshots and personal UUIDs/links are credentials: keep `happ-vip.json`, `happ-users.json` and `happ-user-events.json` under `/etc/sing-box-admin/` mode `0600`, never publish them. The VIP snapshot includes protected inbound TLS material. Do not include personal UUIDs in audit events or infer user identity from a shared client IP.
- `9445` is a VLESS inbound, not an admin endpoint.
- TrustTunnel upstream profiles hold endpoint credentials: keep `/etc/sing-box-admin/trusttunnel-servers.json` (`0600`) and `/etc/sing-box/trusttunnel-clients/*.toml` (`0640 root:sing-box`) out of the repository, backups, logs and screenshots. Each client listens only on loopback behind a random SOCKS5 username/password, runs unprivileged and always with the kill switch on, so an unreachable endpoint fails closed; never set `killswitch_enabled = false` or add `exclusions`, because the client would then connect directly and expose the server's own address. Do not import a profile that points to this host's own HAPP TrustTunnel endpoint as a route.
- Trojan, Hysteria2 and TrustTunnel secrets (`trojan_password`/`hy2_password`/`tt_password` in `happ-users.json`, `/etc/sing-box-happ-server/trusttunnel/credentials.toml`, the `trojan://`, `hysteria2://` and `tt://` links, their QR codes and subscriptions containing the Trojan or Hysteria2 link) are credentials: never log, publish or screenshot them. `happ-protocols.json` is mode `0600`; the TrustTunnel files and the generated TLS key are `0640 root:sing-box` in `0750` directories, so keep unrelated accounts out of the `sing-box` group. The self-signed certificate is pinned in the links (`pcs` for Trojan, `pinSHA256` for Hysteria2, embedded DER for TrustTunnel); `allowInsecure`/`insecure=1` are emitted only together with that pin and never for a custom certificate. Ports `9446`/`9447`/`9448` are client-facing inbounds, not admin endpoints.
- Before publishing, run a secret scan and inspect `git diff --cached`.
- Rotate credentials that were ever pasted into chat, logs or test output.
