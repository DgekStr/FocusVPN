Единый VPN-шлюз и административная панель для WireGuard, sing-box и HAPP. Текущая версия `2.1.8` объединяет изменения от 6-8 октября 2026 года после `v2.1.7`. Последующие исправления интерфейса публикуются в `master` без повышения версии; предыдущие теги и релизы не изменяются. Базовый релиз `v1.0` закреплён коммитом `3f48b16`, история Git не переписывается.

## Импорт Xray Reality без fingerprint - 2026-10-09

- Исправлен отказ импорта полного клиентского Xray JSON в разделе «VPN-серверы», если `realitySettings.fingerprint` пустой, отсутствует или равен `null`. Импортёр добавляет обязательный для sing-box Reality-клиента uTLS с fingerprint `chrome`; непустое явно заданное значение сохраняется. Обычный TLS не меняется.
- Полный клиентский JSON используется как источник VPN outbound. Его клиентские DNS, inbounds и routing rules не заменяют серверные настройки; адрес, UUID, public key, short ID и flow импортируемого профиля сохраняются.
- На целевом сервере воспроизведён отказ sing-box `1.14.2`: `uTLS is required by reality client`. Исправленные empty/null/missing варианты проходят полный batch import и настоящие gateway/HAPP checks без записи рабочих конфигураций. Backend панели обновлён отдельно; VPN-процессы, настройки, реестр и ключи не менялись.
- Прошли 170 Python-тестов, включая 25 проверок импорта/синхронизации маршрутов. Версия остаётся `2.1.8`, существующие тег и релиз не менялись.

## Внешний доступ после установки - 2026-10-09

- Новая установка сразу настраивает IPv4-доступ к панели `https://<IP>:7445` без VPN: `FOCUSVPN_ADMIN_NETWORK=0.0.0.0/0`. Отсутствующий или пустой ACL получает это значение; явно заданный непустой CIDR сохраняется при обновлении. Для ограничения доступа укажите нужную IPv4-сеть в `/etc/focusvpn/focusvpn.env` и перезапустите `sing-box-admin`.
- Авторизация панели и токены подписок остаются обязательными. HTTP-backend `9443` слушает только `127.0.0.1`; внешний доступ к wg-easy `51821` остаётся заблокирован. Самоподписанному сертификату нужно явное доверие; для обычного браузерного доступа рекомендуется доверенный сертификат.
- На VPS подтверждён доступ с внешнего Windows-клиента с проверкой TLS: `/login` отвечает `401`, закрытые страницы перенаправляют на вход, неверный пароль отклоняется. `9443` и `51821` извне недоступны; пароли, ключи, VPN-конфигурации и процесс wg-easy не менялись.
- Прошли 168 Python-тестов, включая 17 проверок установщика. Проверены CLI на свежем env-шаблоне, повторная настройка, сохранение custom ACL и реальный Bash/Python render nft-правил. Полный привилегированный запуск на чистой VM не выполнялся; версия остаётся `2.1.8`, тег и релиз не менялись.

## Исправление установки wg-easy - 2026-10-09

- Перед запуском контейнера установщик загружает модули WireGuard и legacy IPv4/IPv6 NAT/filter на хосте. Добавлена зависимость `kmod`, список модулей сохраняется в `/etc/modules-load.d/focusvpn-wg-easy.conf` для загрузки при старте ОС. Если модуль недоступен, установка прекращается с указанием его имени.
- Исправлен постоянный HTTP 500 `/api/client` после ошибки `ip6tables (legacy): can't initialize ... table nat`. На хосте с nftables необходимый `ip6table_nat` может присутствовать, но не быть загружен; изменение пароля или увеличение числа повторов не исправляет отсутствие WireGuard-интерфейса.
- При повторной установке существующий `unhealthy` контейнер перезапускается после подготовки ядра, без сброса базы и служебного пароля. Исправный контейнер не перезапускается ради восстановления; штатное удаление одноразовых INIT-переменных сохранено.
- На Ubuntu 24.04.5 с ядром 6.8.0-31 подтверждены запуск `wg0`, авторизованный API, состояние `healthy`, запуск панели/Nginx и сохранность паролей, ключей и конфигураций. Версии sing-box `1.14.2` и wg-easy `15.4.0` соответствуют установщику. Сетевой ACL панели не расширялся; прямой запрос с неразрешённого адреса получает `403`.
- Прошли 166 Python-тестов, включая 15 проверок установщика. Проверено восстановление существующей установки, а не полный привилегированный запуск на чистой VM. Версия проекта остаётся `2.1.8`; предыдущие тег и релиз не изменены.

При запуске панели удаляются также данные ранее удалённых пользователей. Запоздавшие замеры не восстанавливают удалённый профиль; VIP и остальные зарегистрированные пользователи сохраняются.

Под именем расположена шкала из 25 сегментов: без трафика прозрачная, при росте суммарной скорости загорается от зелёного до красного со световым переходом. Устаревшие данные не подсвечиваются, предпочтение reduced-motion учитывается.

Пропуски замеров не заменяются выдуманными скоростями. Блок имеет ширину соседних секций, фиксированную высоту 880 px на desktop и 1120 px в компактной раскладке, внутреннюю прокрутку списка.
- Исправлены позднее сопоставление аутентификации и перенос накопленных байтов. Неопределённые наблюдения остаются приватными и не создают псевдопользователя в отчётах. Для закрытого соединения требуется уникальное совпадение IP, порта, назначения и времени, а не догадка по одному IP.
- Подписки используют внешний HTTPS-порт 7445 вместо закрытого backend 9443. Адрес можно переопределить в Настройках; установщик заполняет пустой адрес и сохраняет пользовательский. Токены, UUID и ключи существующих пользователей не меняются.

Профиль передаётся в теле VIP и персональных подписок через `happ://routing/onadd/...`; старые отдельные VLESS-ссылки требуют повторного импорта подписки для получения правил.
- Создание HAPP-пользователя перенесено в диалог с фокусом, отменой, Escape и CSRF. Даты журнала персонального доступа отображаются в русском формате UTC. Маршрут по умолчанию отмечается зелёным индикатором, в таблицу WireGuard добавлена кнопка удаления клиента.
- Исправлено определение IPv4 установщиком через `ip -4 route get 1.1.1.1` для маршрутов без поля `src`. Preflight проверяет весь runtime до системных изменений; Python компилируется перед запуском панели. Регрессионный тест выполняет реальные команды копирования в TEMP и проверяет новые ресурсы, версию и библиотеку графиков.
- API wg-easy повторно опрашивается при временных 5xx на первом запуске; ошибки авторизации не скрываются повторами. Исправлены uptime LXC и отображение минут, а при переключении на основной шлюз недостающие scoped FORWARD/NAT правила проверяются и добавляются с откатом при ошибке.

Проверены 163 Python-теста, оба Node.js-набора интерфейса, Bash/Python/JavaScript-синтаксис и publication checks. Релиз развёрнут на рабочем сервере с приватной резервной копией SQLite и проверкой очистки на её копии. ## Ранние дополнения, включённые в v2.1.8

- Маршрут по умолчанию в таблице VPN-серверов отмечается зелёным индикатором с доступной подписью вместо `active`. Статус службы не меняется.
- Блок «Подключения HAPP» расположен выше «Пользователи HAPP». Высота фиксирована на 880/1120 px, прокрутка и доступ ко всем строкам сохранены. Удалено пояснение под таблицей активного трафика.
- Создание HAPP-пользователя перенесено в модальное окно в стиле панели. Сохранены обязательное имя, необязательный срок UTC и CSRF-защита; работают фокус, сброс формы, отмена, Escape и закрытие по фону. CSS и JS имеют обновлённые адреса для сброса браузерного кэша.
- VIP и персональные HTTP-подписки получают профиль `FocusVPN Direct`: 201 явно заданное `domain:`-исключение идёт через обычное подключение клиента, остальные назначения остаются на VPN. JSON профиля кодируется в Base64 и передаётся строкой `happ://routing/onadd/...` в теле подписки, без большого HTTP-заголовка.
- Имя профиля неизменно, а `LastUpdated=1791417601` обозначает стабильную ревизию правил. UUID, ключи, токены и адреса подписок не меняются; ранее импортированные отдельные VLESS-ссылки продолжают работать, но не получают исключения автоматически.
- После обновления подписки нужно дождаться готовности geo-файлов и переподключить HAPP. Исходный JSON сервера может не измениться: профиль маршрутизации хранится отдельно, а уже запущенный Xray не пересобирается при обновлении подписки. IP-проверки из списка исключений показывают реальный IP клиента.
- Установщик проверяет наличие обязательных модулей, статических файлов и файла версии до системных изменений, копирует весь обновлённый runtime и компилирует Python-код до запуска панели. Рабочие шаблоны, пароль и данные HAPP не заменяются значениями из Git.

При раннем обновлении на сервере проверены семь действующих подписок по LAN и публичному HTTPS, сохранение ключей/UUID/токенов и PID VPN-служб. В Windows HAPP 4.3.0.610 подтверждены импорт, выбор профиля и наличие 200 правил ранней ревизии; прямой выход после клиентского переподключения пока не подтверждён. Полный привилегированный запуск обновлённого установщика требует отдельной тестовой VM.

- Автономный установщик из Git устанавливает системные зависимости, панель и службы systemd, проверяет SHA-256 sing-box и безопасно запрашивает пароль панели.
- Перед установкой показывает пакеты и службы и запрашивает подтверждение. Автоматически запускает Nginx и контейнер wg-easy; setup wg-easy закрыт извне и доступен через SSH-туннель. При старых WireGuard-конфигах предлагает отмену или перенос в резервную копию.
- После установки печатает состав установленных компонентов и HTTPS-адрес панели `https://<IP>:7445`; для сертификата по IP используется самоподписанный сертификат.


## HAPP: точность статистики

Для сопоставления имени пользователя с активным соединением используется журнал аутентификации VLESS, а не только IP-адрес. Накопительные итоги учитывают только новые приросты счётчиков соединений и сохраняются после очистки подробной истории. При первом запуске они заполняются по записям, которые ещё есть в SQLite; данные, уже удалённые по сроку хранения, восстановить нельзя. Кнопка сброса удаляет итог только выбранного профиля; текущие значения счётчиков становятся начальной точкой, после сброса учитываются лишь новые байты.

В пользовательских списках, графиках и итогах отображаются только подтверждённые журналом учётные записи реестра и защищённая группа VIP. Наблюдения без установленного имени хранятся приватно для позднего сопоставления и не создают пользователя «Не определён». Для закрытого соединения поздняя аутентификация учитывается только при уникальном совпадении IP, порта, назначения и времени; накопленные байты переносятся один раз. Доступ VLESS требует зарегистрированного UUID, отсутствие имени в наблюдении не означает анонимную авторизацию.

Исторический график и накопительные итоги — наблюдаемые оценки, а не точные данные для расчётов. При разрыве или перезапуске соединения могут потеряться последние байты, которые сборщик не успел зафиксировать. Полные HTTPS-адреса страниц и их содержимое недоступны.

Удаление персонального пользователя из HAPP Server удаляет его данные из четырёх таблиц статистики, включая историю и накопительные итоги. После обновления такая очистка применяется и к ранее удалённым профилям; перед обновлением сделайте резервную копию SQLite. Отмена неуспешного применения VPN-конфигурации не удаляет статистику. Отключение или истечение срока не равны удалению: данные зарегистрированного профиля сохраняются. Административный журнал действий сохраняет запись об удалении.

| HAPP Server | `/happ-server` |
| Настройки | `/settings` |
| Журнал переключений | `/gateway-journal` |
| История HAPP | `/happ-history` |
| Информация о подписке | `/happ-info` |
| HAPP VLESS inbound | публичный адрес, TCP `9445` |

IP-адрес панели определяется установщиком по основному маршруту сервера; HTTPS доступен на порту `7445`. Для IP используется самоподписанный сертификат, поэтому браузер покажет предупреждение. Backend панели слушает только `127.0.0.1:9443` за Nginx и не должен публиковаться напрямую. Для постоянного домена настройте DNS и сертификат доверенного центра отдельно.

Подписки HAPP по умолчанию используют тот же внешний HTTPS-порт `7445`, а не закрытый backend `9443`. Сохранённые ссылки со старым портом нужно заново скопировать из панели и импортировать в клиент; токены и VPN-ключи не меняются. Клиент должен доверять сертификату HTTPS. Другой публичный адрес подписок можно явно задать в Настройках.

Установщик сохраняет `FOCUSVPN_HAPP_SUBSCRIPTION_BASE_URL=https://<IP-адрес-сервера>:7445` в `/etc/focusvpn/focusvpn.env`, если значение отсутствует или пустое. Уже настроенный непустой адрес подписок сохраняется без изменений.

## Установка

Для воспроизводимой установки релиза `v2.1.8` на Debian 12+ или Ubuntu 22.04+:

```bash
curl -fsSL https://raw.githubusercontent.com/DgekStr/FocusVPN/v2.1.8/scripts/bootstrap.sh | sudo bash -s -- v2.1.8
```

Для установки текущей ветки разработки используйте `master`:

```bash
curl -fsSL https://raw.githubusercontent.com/DgekStr/FocusVPN/master/scripts/bootstrap.sh | sudo bash -s -- master
```

Bootstrap клонирует выбранную ветку или тег во временный каталог с правами `0700`, запускает `scripts/install.sh` и удаляет копию после завершения. Для интерактивного ввода пароля требуется терминал. Пароль не передаётся в аргументах командной строки или переменных окружения; в `/etc/sing-box-admin/auth.json` сохраняется хеш scrypt с солью и правами `0600`.

Если установка прервалась с `could not determine the server IPv4 address for the panel URL`, повторите команду для `master` после получения исправления. Не удаляйте `/etc/sing-box-admin/auth.json`: существующие учётные данные и файлы конфигурации сохраняются. Адрес панели теперь определяется через `ip -4 route get 1.1.1.1`, поскольку обычный маршрут по умолчанию может не содержать поле `src`; эта команда только запрашивает маршрут у ядра и не отправляет сетевые пакеты.

Дополнительные параметры:

- wg-easy запускается и настраивается автоматически, служебные учётные данные подключаются к API панели. Прямой доступ к порту `51821` извне закрыт.
- `--enable` проверяет реальные конфигурации и включает VPN-службы. Не используйте этот параметр до заполнения конфигураций шлюза, HAPP и wg-easy.

Установка актуальных дополнений из клонированного репозитория:

```bash
git clone --branch master https://github.com/DgekStr/FocusVPN.git
cd FocusVPN
sudo ./scripts/install.sh
```

Для обновления существующего клона `master` сначала получите изменения через `git pull --ff-only`, затем запускайте установщик после резервного копирования и в согласованное окно обслуживания. Это полноценная установка с apt/Docker/Nginx, а не бесшовный deploy одного UI-файла. Не запускайте `--enable`, если VPN-конфигурации не заполнены. Секретный ключ HTTP-подписок и пользовательские данные должны сохраняться на сервере, а не восстанавливаться из шаблонов Git.

Затем настройте `/etc/focusvpn/focusvpn.env`, заполните реальные файлы `/etc/sing-box/config.json`, `/etc/sing-box-happ-server/config.json` и `/etc/sing-box-admin/happ-server.json` и только после этого выполните `sudo ./scripts/install.sh --enable`. Файл `/etc/sing-box-admin/wg-easy-api.json` уже настроен установщиком. Автоматически выбранный IP для WireGuard является адресом сервера, а не гарантированным публичным адресом за NAT: для удалённых клиентов проверьте адрес и проброс UDP `51820`. Остальные VPN-службы с шаблонными конфигурациями не включаются.

## Проверка клона Git

Проверка опубликованного тега из PowerShell без установки с правами администратора:

```powershell
$clone = Join-Path $env:TEMP ('FocusVPN-v2.1.8-' + [guid]::NewGuid().ToString('N'))
git clone --depth 1 --branch v2.1.8 https://github.com/DgekStr/FocusVPN.git $clone
Push-Location $clone
try {
    .\scripts\validate.ps1
    py -3 -m unittest discover -s scripts -p 'test_*.py' -q
    node scripts\test_panel_checks.js
    node scripts\test_happ_stats_ui.js
    & 'C:\Program Files\Git\bin\bash.exe' scripts/bootstrap.sh --help
    & 'C:\Program Files\Git\bin\bash.exe' scripts/install.sh --help
} finally {
    Pop-Location
}
```

В Linux вместо `C:\Program Files\Git\bin\bash.exe` используйте `bash`. Текущий набор содержит тесты Python, два набора проверок интерфейса на Node.js и publication checks. Проверки включают удаление и защиту статистики от поздних замеров, 25-сегментные индикаторы, редактор, HAPP-мастер/ключи, исключения подписки, preflight и копирование runtime установщиком, сохранение рабочих данных. Для проверки ветки разработки клонируйте `master` вместо тега `v2.1.8`.

## Репозиторий

- `server/panel/` — код панели на Python и обработчики HAPP/WireGuard.
- `server/panel/static/` — CSS и JavaScript.
- `server/libexec/` и `server/systemd/` — системные команды и службы.
- `server/config/` — безопасные шаблоны конфигураций.
- `scripts/` — установщик, bootstrap, тесты и средство предварительного просмотра.
- `docs/OPERATIONS.md` — эксплуатация и развертывание.
- `docs/PROJECT_STATUS.md` и `docs/ROADMAP.md` — статус и следующие задачи.
- `docs/CHANGELOG.md` — изменения v2.1.8 и более ранних релизов.
- `VERSION` — версия установленной системы.

Секреты, реальные UUID и VLESS-ссылки, ключи Reality, данные Basic Auth, секрет API wg-easy, рабочие базы и введённые администраторами конфигурации в Git не включаются. Скриншоты в `docs/screenshots/` сделаны на синтетических данных и показывают интерфейс v2.0 без новых карточек метрик и графика из v2.1.
